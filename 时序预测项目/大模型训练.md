### 二.数据处理
  **需要输入输出数据对**
  **输入数据右移一个token就是输出数据对,上下文长度不变**
  1. 上下文长度content_length
    大模型每次允许输入的token数
    样本会分段输入
  2. 移动步幅stride
    大模型上下文窗口移动的步幅
    越小重复输入的token越多,越大则越少,当stride大于context_length时,完全不会重复
  3. batchsize
    每次输入模型的样本数.
### 三.大模型
  1. 可以分为三层
    嵌入层->transformer层->输出层
    1. 嵌入层
      文字转换为向量
    2. transformer层
      核心环节,捕捉上下文语意,理解意思
    3. 输出层
      通常是个简单的全连接层,输出每个单词的预测结果
  2. 嵌入层
    1. 需要一个向量矩阵,行数为token数,列数随意,列数表示这个词元的向量维度,维度越大,向量的信息越大
    2. 输入不能是词元,而应该是向量
    3. 向量除了其本身的维度信息,还应该再加上这个词的位置信息,再输入给大模型,有两种方法获取位置信息
      - 训练法
      - 公式法

      现在相对位置编码更常用
    4. 取向量的方式
      - 可以是用one-hot编码来取,每一个token对应一个一行矩阵,其中只有其对应位置是1,其他都是0,这个矩阵乘上向量矩阵就得到了他的向量,于是向量就变成了一个线性运算
    5. 注意力矩阵
      对一个向量,将其与其他所有向量求点积,把在它后面的词记为负的无穷大,这样就不会注意到后面的词,避免后续训练时已知后续输出.
      得到的结果再归一化,作为系数乘上对应向量,得到和原来大小一样的新向量,就是该向量的注意力矩阵.其他向量同理
      注意力向量表现了当前向量与其他向量的相关度
      这里引入QKV矩阵:
      - 因为每个向量都有三种操作
      - 一是作为查询者,查询其他向量和它的相关度
      - 二是作为被查询者,被用来点乘,计算和查询者的相关度
      - 三是生成新的注意力向量
      于是把向量做成三个,Q,K,V向量,Q负责查询,K复制被查询,V负责最后生成向量
      QKV向量的获取是通过Wq,Wk,Wv矩阵得到的,这三个权重矩阵是可以更新的,会在训练时找到最好的权重矩阵
      注意力矩阵是个方阵
  3. Transformer
    多层,输入和输出的维度得是一样的,会进行多次Transform
    需要做归一化，残差连接
  4. 输出层
    会计算损失，确定下一个词，候选词词出现的概率。
    不是选概率越大的词越好，因为局部最优不一定全局最优
    - tempreture参数
      tempreture越大，输出越多样
    可以限定候选词的数量
    - TopK，
      只在概率最大的k个候选中选
    - TopP
      从大到小，选取概率之和超过P的部分
    - minP
      舍去概率小于P的词

### 梯度是什么
梯度就是损失函数对参数的偏导数，表示：参数往哪个方向稍微改一点，损失会上升/下降多少。

### Backbone（骨干网络）
**Backbone 就是大模型里负责把输入转换成通用隐状态（hidden state）的主干 Transformer 主体，是模型的核心特征提取器，和具体下游任务无关，可以被复用**。
|名词	|作用|	是否任务相关|
|:-|:-|:-|
|Backbone	|提取通用上下文语义特征，输出 hidden state|	 任务无关，通用基座|
|Head	|把特征转为任务需要的输出	|任务专属|
|Neck（颈层）	|特征融合、变换，LLM 很少提，CV 用得多|	-|

#### 1. `avg_loss` 是什么
它是**每个 epoch 的平均损失**，用的是 **BCEWithLogitsLoss**（带 logits 的二元交叉熵）。

- 模型对每条样本输出一个原始分数 `logit z`（还没有做 sigmoid 压缩）
- 损失公式（对单条样本）：`loss = -[ y·log(σ(z)) + (1-y)·log(1-σ(z)) ]`，其中 `σ(z)=1/(1+e⁻ᶻ)` 是点击概率
- `avg_loss` = 这个 epoch 内**所有 batch 的平均 loss**

**含义**：它衡量的是**模型在训练集上拟合得有多好**——loss 越低，模型对训练样本标签的预测越准。它是 "能不能学进去" 的指标。
==loss越低，不代表AUC就会变高==
注意：我们数据正例率只有 3.2%，极度不平衡，所以这个 loss 数值本身偏高是正常的，**不要拿它和别的数据集比绝对值**。
#### 为什么每轮 AUC 有升有降

AUC 是在**验证集**（15.3 万行）上算的。每跑一个 epoch，模型权重被整体更新一遍，验证 AUC 就会有起伏。原因：

- **还没收敛**：模型还在 "探索" 参数空间，每轮梯度更新都会让排序略微变化，所以 A1.5→0.57、0.5698 这种小波动很正常
- **学习率过大**：每步更新步子大，容易在某轮 "冲过头"，AUC 就掉一下，下轮又回来
- **验证集是固定抽样的**：每轮都是同一批验证样本，所以波动纯粹来自模型本身，不是数据问题

> 判断时**看趋势而不是单点**：AUC 总体往上、波动变小，就是健康的；一直不涨说明该换方向。

（你之前 200 行小样本那次 AUC 在 0.42~0.63 乱跳，那是因为**验证集只有 20 行**，样本太少方差极大。真实数据 15 万行验证，波动就很小了。）
#### AUC 是怎么算出来的

AUC = **ROC 曲线下的面积**。一步一步：

**第一步：画出 ROC 曲线。** 把所有验证样本按模型预测的点击概率从高到低排序，然后对**每一个阈值 t**，计算两个比率：

- 真正率 TPR = 预测为正的样本中、确实是正例的比例（召回率）
- 假正率 FPR = 预测为正的样本中、其实是负例的比例

把每个阈值对应的 `(FPR, TPR)` 连成一条曲线，就是 ROC 曲线。
### 学习是怎么做到的
"学习"的本质就是**不断修改模型的参数（权重/偏置）**，让损失越来越小。数据、代码、vocab 都不动，动的只有那些数字。

#### 你的 DeepFM 里到底有哪些"可被修改的参数"

| 部分 | 参数 | 它学到的是什么 |
|---|---|---|
| 每个类别的 Embedding 表 | 每个类别取值对应一个稠密向量（如 16 个数） | 给每个 `user_id`/`item_id` 之类学到语义向量 |
| FM 一阶（first_order） | 每个类别取值一个权重 | 每个取值的"独立影响力" |
| 稠密特征线性层 `dense_linear` | 每个数值特征一个权重 | 数值特征的线性作用 |
| MLP（`self.mlp` 里的所有 Linear） | 层间权重 + 偏置 | 捕捉高阶特征交互 |

这些加起来就是你训练时打印的"模型参数 3.24M"——**三百多万个要改的数**。

#### 修改的过程（梯度下降）

训练脚本里每 batch 就四行，核心在这：
```python
logit = model(sp, dn)      # 1. 前向：数据 → 预测
loss = loss_fn(logit, lb)  # 2. 算损失（错得有多离谱）
loss.backward()            # 3. 反向传播：算出"每个参数该往哪改"
opt.step()                 # 4. 优化器：真的去改参数
opt.clear_grad()           #    清空梯度，准备下个 batch
```

**第 3、4 步是关键。** 拿一个权重 `w` 举例：

1. `loss.backward()` 用链式法则算出梯度 `g = ∂loss/∂w`——它告诉你：**`w` 稍微增大一点，loss 是升还是降、升多少降多少**
2. `opt.step()` 按梯度把 `w` 挪一步：
   ```
   w ← w − 学习率 × 梯度
   ```
   意思就是：**往让 loss 下降的方向走**。

举个最简单的数例（假设单权重，忽略 Adam 的细节）：
```
现在 w = 2.0，梯度 g = +0.1，学习率 lr = 0.01
→ 梯度为正表示"w 变大 loss 会涨"，所以反向走：
w = 2.0 − 0.01×0.1 = 1.999
```
每走一步，loss 就小一点。训练几百次这样的小调整，参数就从随机值慢慢变成"好用的值"。

#### 你用的 Adam 优化器

`paddle.optimizer.Adam(learning_rate=0.001)` 做的不是朴素 `w - lr·g`，而是加了两个机制：
- **动量**：像小球滚坡，方向不来回抖
- **自适应学习率**：每个参数根据自己的梯度大小单独调步子，稀疏的 Embedding 参数（大量类别）尤其需要这个

效果是收敛更快、更稳，但本质还是"**顺着梯度反方向修改参数**"。

#### 一个容易混淆的点

被修改的**只有 `model.parameters()` 里的权重**：
- ❌ 不改你的训练数据
- ❌ 不改代码
- ❌ 不改类别 vocab（那些 id 是预处理时定死的）
- ❌ 不改学习率、epochs 这些超参数（它们是"设置"，不是"学出来的"）

**Embedding 格外值得一提**：训练前每个类别的向量是随机初始化的，训练后它们就变成了"在这个任务上有意义的表示"——比如相似点击行为的类别会学到相近的向量。这是整个 CTR 模型的核心价值所在。

### 稠密和稀疏特征
这是特征在模型输入里的两种形态，对应你数据里的**两类字段**。

#### dense（稠密）= 13 个数值特征

就是 `I1..I13` 那 13 个数字，以**连续 float 值**喂给模型：
```
dense = [5.0, 22.0, 0.0, ..., 302.0]   ← 13 个真实数值
```
叫 "dense"（稠密）是因为：每个数字本身**就有含义**、都有取值，不需要任何查表，直接进线性层/MLP 就行。

#### sparse（稀疏）= 26 个类别特征

就是 `C1..C26`，以**整数 id** 喂给模型：
```
sparse = [1, 3, 0, ..., 42]   ← 26 个类别id
```
叫 "sparse"（稀疏）是因为：它原本的形态是 **one-hot 向量**——比如 C1 有 4 万个可能取值，那 C1 就该是一个 4 万维的向量，其中只有 1 位是 1、其余 39999 位全是 0（**极度稀疏**）。存储和计算都太浪费，所以我们压缩成只记"是哪个 id"：`3` 就代表"第 3 个取值"。

#### 两者在模型里走不同的路

```
        ┌─ dense (13个连续数) ──→ 线性层 ──┐
输入 ───┤                                  ├──→ FM交叉 + MLP → 点击概率
        └─ sparse (26个id) ───→ Embedding查表 ─┘
```

- **dense**：数字本身直接用，学一个权重
- **sparse**：id 只是"下标"，真正的数值是去 Embedding 表里**查出那个向量**（训练中学出来的表示）

#### 一句话对照

| | dense 特征 | sparse 特征 |
|---|---|---|
| 对应字段 | I1..I13（数值） | C1..C26（类别） |
| 喂给模型的是 | 真实数字 | 整数下标 |
| 模型怎么用 | 线性层/MLP | Embedding 查表 |
| 为什么叫稠密/稀疏 | 每个数都有意义 | 原始 one-hot 极多 0，故"稀疏" |

名字里的"稠/稀"说的是**特征原本的表达是否大多为零**：数值是稠的（都有值），类别 one-hot 是稀的（几乎全 0）。
