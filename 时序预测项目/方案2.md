# 方案 2：用 Live U 盘将 4T Ubuntu 迁移到 2T SSD

目标是把当前 Ubuntu 文件级复制到 2T SSD，并让新盘可独立启动。迁移时将 4T 系统以只读方式作为 rsync 来源。新盘仍采用 LUKS 加密和 LVM，但 UUID/卷名会不同；文件 UID/GID、ACL、扩展属性等由 rsync 保留。

> **高风险操作。** 按你的要求不备份 2T SSD；重新分区会清空这块盘上的所有分区、文件和 `linux-home-data-20261111.luks` 镜像，无法从本方案恢复。必须核对序列号，任何信息对不上就停止。以下命令只在远程主机的 Live U 盘终端执行，不要在原 Ubuntu 正常运行时执行。

## 设备与容量

| 物理盘 | 型号与序列号 | 当前用途 |
|---|---|---|
| 10T HDD | Seagate ST10000VN0004-1ZD101，`ZA26E3WC` | NTFS，约 5.5T 可用；本方案不使用、不改动。 |
| 4T NVMe（源） | ZHITAI TiPro9000，`ZTC84T0AB26093002A` | p1 EFI、p2 `/boot`、p3 LUKS → LVM `ubuntu-vg/ubuntu-lv` → ext4 `/`；删除 nova/data 后，根分区已用约 1.09TB（0.99TiB）。 |
| 2T NVMe（目标） | ZHITAI TiPlus7100s，`ZTA82T0AB26021386W` | 目前有 NTFS 分区、数据和 `linux-home-data-20261111.luks`；迁移时整盘会被清空。 |

目标根分区建议保留数据不超过 **1.3TiB（约 1.43TB）**。当前实测约 0.99TiB，已低于建议门槛；迁移当天仍需重新检查，因为后续新增数据会增加用量。不要删除用途不明的系统文件；若迁移前超过门槛，先清理或重新规划数据盘。

## 1. 清理并启动 U 盘

在当前 Ubuntu 清理确认不需要保留的数据，然后确认根盘使用量：

```bash
df -hT /
sudo du -xhd1 / 2>/dev/null | sort -h
sudo du -xhd1 /home 2>/dev/null | sort -h
```

用 Rufus 从 Ubuntu 官方 ISO 制作 UEFI 启动 U 盘。将 U 盘插到远程主机现场，接显示器和键盘，进入主板 Boot Menu，选择 UEFI USB，进入“试用 Ubuntu/Live”，不要选择安装系统。

## 2. Live 环境识别磁盘

打开 Terminal，按序列号确认三块物理盘，并设置稳定路径：

```bash
sudo lsblk -d -o NAME,SIZE,MODEL,SERIAL,TYPE
SRC=/dev/disk/by-id/nvme-ZHITAI_TiPro9000_4TB_ZTC84T0AB26093002A
DST=/dev/disk/by-id/nvme-ZHITAI_TiPlus7100s_2TB_ZTA82T0AB26021386W
HDD=/dev/disk/by-id/ata-ST10000VN0004-1ZD101_ZA26E3WC
readlink -f "$SRC" "$DST" "$HDD"
```

输出必须分别是 4T 源盘、2T 目标盘、10T HDD。若不是，停止。本方案不会挂载或写入 10T HDD。

```bash
sudo lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINTS "$(readlink -f "$DST")"
for p in "${DST}-part1" "${DST}-part2" "${DST}-part3" "${DST}-part4" "${DST}-part5"; do sudo umount "$p" 2>/dev/null || true; done
if sudo lsblk -nrpo MOUNTPOINTS "$(readlink -f "$DST")" | grep -q .; then echo '目标盘仍有挂载点，停止'; exit 1; fi
```

确认输出中目标盘序列号为 `ZTA82T0AB26021386W` 且没有挂载点。若不能确认目标盘、或 2T 盘上的任何数据还要保留，停止，不要继续。

## 3. 只读挂载源系统

解锁 4T 源盘的 LUKS 并激活 LVM，输入原系统的开机解锁密码：

```bash
sudo cryptsetup open "${SRC}-part3" source_crypt
sudo vgchange -ay ubuntu-vg
sudo lvs -o lv_name,vg_name,lv_size,devices
```

确认存在 `ubuntu-vg/ubuntu-lv` 后，根、`/boot` 以只读方式挂载。注意：源盘 p2 是 `/boot`，**不是根分区**；真正的根在 LUKS/LVM 里面：

```bash
sudo mkdir -p /mnt/src /mnt/srcboot
sudo mount -o ro,noload /dev/ubuntu-vg/ubuntu-lv /mnt/src
sudo mount -o ro,noload "${SRC}-part2" /mnt/srcboot
sudo df -hT /mnt/src /mnt/srcboot
```

确认 `/mnt/src` 是 Ubuntu 根目录（能看到 `etc`、`usr`、`home`），`/mnt/srcboot` 能看到内核文件。若不符，停止。

## 4. 重建目标盘并复制

**以下会清空整块 2T SSD。再次核对 `DST` 的序列号必须是 `ZTA82T0AB26021386W`。** 分成 EFI 1GiB、`/boot` 2GiB、其余空间做加密根盘：

```bash
readlink -f "$SRC" "$DST" "$HDD"
sudo sgdisk --zap-all "$DST"
sudo sgdisk --clear \
  --new=1:1MiB:+1GiB --typecode=1:ef00 --change-name=1:EFI \
  --new=2:0:+2GiB --typecode=2:8300 --change-name=2:BOOT \
  --new=3:0:0 --typecode=3:8309 --change-name=3:CRYPTROOT "$DST"
sudo partprobe "$DST"
sudo udevadm settle
sudo lsblk -o NAME,SIZE,PARTTYPE,PARTLABEL "$DST"
```

确认新盘出现 p1/p2/p3 后，建立 EFI、boot 和 LUKS/LVM/ext4 根卷。LUKS 可输入与旧盘相同的口令，但这是新的加密容器：

```bash
DSTP1="${DST}-part1"
DSTP2="${DST}-part2"
DSTP3="${DST}-part3"
sudo mkfs.fat -F32 -n EFI "$DSTP1"
sudo mkfs.ext4 -F -L boot "$DSTP2"
sudo cryptsetup luksFormat --type luks2 "$DSTP3"
sudo cryptsetup open "$DSTP3" target_crypt
sudo pvcreate /dev/mapper/target_crypt
sudo vgcreate target-vg /dev/mapper/target_crypt
sudo lvcreate -l 100%FREE -n root target-vg
sudo mkfs.ext4 -F -L ubuntu-root /dev/target-vg/root
```

挂载目标盘并复制系统文件。`/swap.img` 不复制，之后重新创建；运行时目录、外部挂载目录和单独的 `/boot` 也不通过根目录这次 rsync 复制：

```bash
sudo mkdir -p /mnt/dst
sudo mount /dev/target-vg/root /mnt/dst
sudo mkdir -p /mnt/dst/boot
sudo mount "$DSTP2" /mnt/dst/boot
sudo mkdir -p /mnt/dst/boot/efi
sudo mount "$DSTP1" /mnt/dst/boot/efi
sudo rsync -aHAXSx --numeric-ids --info=progress2 \
  --exclude=/dev/*** --exclude=/proc/*** --exclude=/sys/*** \
  --exclude=/run/*** --exclude=/tmp/*** --exclude=/var/tmp/*** \
  --exclude=/mnt/*** --exclude=/media/*** --exclude=/lost+found \
  --exclude=/boot/*** --exclude=/swap.img \
  /mnt/src/ /mnt/dst/
sudo rsync -aHAXS --numeric-ids --info=progress2 /mnt/srcboot/ /mnt/dst/boot/
```

复制后、修改系统配置前，分别做 checksum dry-run。输出任何差异或报错都先停止并处理：

```bash
sudo rsync -aHAXSxnc --numeric-ids --delete --itemize-changes \
  --exclude=/dev/*** --exclude=/proc/*** --exclude=/sys/*** \
  --exclude=/run/*** --exclude=/tmp/*** --exclude=/var/tmp/*** \
  --exclude=/mnt/*** --exclude=/media/*** --exclude=/lost+found \
  --exclude=/boot/*** --exclude=/swap.img \
  /mnt/src/ /mnt/dst/
sudo rsync -aHAXSxnc --numeric-ids --delete --itemize-changes /mnt/srcboot/ /mnt/dst/boot/
```

## 5. 更新启动映射、验收

源盘与新盘 UUID 不同，必须给目标系统写入新 `fstab`/`crypttab`，再生成 initramfs 和 UEFI GRUB：

```bash
ROOT_UUID=$(sudo blkid -s UUID -o value /dev/target-vg/root)
BOOT_UUID=$(sudo blkid -s UUID -o value "$DSTP2")
EFI_UUID=$(sudo blkid -s UUID -o value "$DSTP1")
CRYPT_UUID=$(sudo cryptsetup luksUUID "$DSTP3")
printf 'UUID=%s / ext4 defaults 0 1\nUUID=%s /boot ext4 defaults 0 2\nUUID=%s /boot/efi vfat defaults 0 1\n' "$ROOT_UUID" "$BOOT_UUID" "$EFI_UUID" | sudo tee /mnt/dst/etc/fstab
printf 'target_crypt UUID=%s none luks,initramfs\n' "$CRYPT_UUID" | sudo tee /mnt/dst/etc/crypttab
for d in dev proc sys run; do sudo mount --rbind "/$d" "/mnt/dst/$d"; sudo mount --make-rslave "/mnt/dst/$d"; done
sudo chroot /mnt/dst /bin/bash -c 'update-initramfs -u -k all && update-grub && grub-install --target=x86_64-efi --efi-directory=/boot/efi --bootloader-id=ubuntu-2t-migration --recheck'
```

若 `chroot` 中命令报错，不要重启切换；先保存错误信息并修复。同步会保留用户数据库和数字 UID/GID。10T HDD 及其他外置数据卷不会自动迁移，需另行挂载配置。

完成后卸载目标盘并关闭映射：

```bash
sync
for d in run sys proc dev; do sudo umount -R "/mnt/dst/$d"; done
sudo umount /mnt/dst/boot/efi
sudo umount /mnt/dst/boot
sudo umount /mnt/dst
sudo vgchange -an target-vg
sudo cryptsetup close target_crypt
```

关机、拔掉 U 盘，在 Boot Menu 选择 2T SSD 启动。登录后检查：

```bash
lsblk -o NAME,SIZE,MODEL,SERIAL,FSTYPE,MOUNTPOINTS
findmnt /
df -hT /
id yao
getent passwd yao xch he
systemctl --failed
```

确认根目录来自 2T SSD、用户权限正确、关键应用正常并成功重启后才算验收。两盘的 LUKS UUID、文件系统 UUID 和 LVM 名称不会相同，迁移不是逐扇区克隆。

当前系统原有 swap 是 `/swap.img` **8GiB 文件**，不是 swap 分区。新系统启动验收后，如需恢复同等 swap，可执行：

```bash
sudo fallocate -l 8G /swap.img
sudo chmod 600 /swap.img
sudo mkswap /swap.img
sudo swapon /swap.img
printf '/swap.img none swap sw 0 0\n' | sudo tee -a /etc/fstab
swapon --show
```
